## Where this app actually spends money

1. **Vercel serverless invocations + duration.** Every API route and every uncached Server Component render is a function invocation. The draft clock cron hits `/api/cron/draft` every 5 min from cron-job.org (that's ~8,600 invocations/month baseline — keep it cheap: bounded queries, early return when no draft is active). Flag: new `export const dynamic = 'force-dynamic'` (kills server-component caching — needs a stated reason), new client-side polling (`setInterval` + `fetch`) or a `useEffect` that refetches on every render/keystroke, sequential external fetches that extend duration (ESPN hangs up to the 8 s `AbortSignal.timeout` each — fan-out must use `mapWithConcurrency` from `lib/concurrency.ts`), and anything that turns one invocation into N (per-row fetches inside a loop).
2. **Supabase egress & compute.** The `players` table (with scouting JSON) is the heavy one — `getPlayers()` is the lean list, `getFAPlayersWithScouting()` for FA views, `getPlayerDetail(leagueId, identity)` for one row; the full-table-with-scouting path was retired (`/api/players?scouting=1` → 410). Flag: `select()` without a column list on `players`/`teams`/`transactions`, a new reader not wrapped in `unstable_cache` keyed by `leagueId`, a reader whose cache tag isn't busted by the mutations that change it (or a mutation that busts `players` when only `rules` changed — over-busting refills cold caches on every request), a `revalidate` lowered below what the data needs (standings/schedule change weekly; rosters change on transactions — tags, not short TTLs), and N+1 patterns (per-team roster counts, per-pick team lookups) where one JOIN or one `inArray()` would do.
3. **Gemini (`lib/gemini.ts`, model `gemini-2.5-flash`).** Call sites: `/api/press-box` (box-score stories), `/api/scout/player-report`, `/api/scout/recommend` (streaming), `/api/scout/bulk-player-prompts`. Costs scale with prompt chars × calls. Flag: a new call site without a `tokenBucket` limit (existing: 10/hour per key), prompts that inline whole rosters/standings when a summary would do, retries on non-transient errors, generation fired from a render/effect instead of an explicit click, and model upgrades (pro-tier) without a stated reason.
4. **Email (Gmail via nodemailer) + WhatsApp (GreenAPI).** `sendEmail` retries up to 3× and WhatsApp only fires for league 1. Gmail has a daily send cap and GreenAPI bills per message. Flag: notifications inside loops (one per pick/player instead of one digest), a new notification type sent to the group for routine events, missing `SEND_WHATSAPP` honor, and any `notify*()` that isn't `await`ed (the message is silently lost — wasted invocation, and the retry loop never runs).
5. **Vercel Blob.** `list()` with no prefix scans the whole store (`/api/upload` GET does this today — pre-existing); photo uploads (`/api/maintenance/player-photos`, `scripts/upload-player-photos-blob.ts`) write hundreds of objects. Flag: new `list()` calls on hot paths, re-uploading unchanged photos, and `del()` loops without batching.
6. **External fetch fan-out (ESPN, Ourlads).** `lib/espn-stats.ts` uses `next: { revalidate: 7d }` per athlete; `lib/ourlads.ts` caches depth charts 24 h under tag `ourlads`. Flag: a new per-player ESPN call on a page render (should be a maintenance action or cached), lowered `revalidate`, and fan-out without `mapWithConcurrency`.
7. **Cron correctness as cost.** `/api/cron/draft` must exit fast when no pick is on the clock; `cuts-alert`/`schedule-reminder` must iterate leagues once per run, not once per team per league. Flag any new cron work that's unbounded in teams × leagues.
8. **Client fetch discipline.** Plain `fetch()` honors `private, max-age` headers; `?t=${Date.now()}` or `cache: 'no-store'` on reads defeats them and multiplies invocations. `no-store` is allowed only on the single refetch right after a mutation (`loadData(fresh = false)` pattern in the transaction panels). The Navbar already fetches `/api/rules` once per auth change — flag new per-component fetches of the same endpoint instead of lifting to the existing `LeagueContext`.
